# Luma 云办公工作器

这个工作器在你自己的 Windows 或 Linux 云电脑上接收员工派来的材料。需要 Node.js 24，可直接复制本目录到云电脑。安装 DSH 插件不会启动它。

## 启动

在云电脑上设置环境变量 `LUMA_WORKER_TOKEN` 为自己生成的至少 24 位随机令牌。进入本目录运行：

```sh
node worker.mjs
```

工作器默认监听云电脑的 `127.0.0.1:8795`。在同一台机器试用时，插件可填写 `http://127.0.0.1:8795`。跨机器连接时，在云电脑上用已配置 TLS 的反向代理将你的 HTTPS 地址转发到该本机端口。在 DSH 的「插件设置 → 云办公服务器」填入该 HTTPS 地址和同一令牌，保存后点击「测试连接」。

可以用 `LUMA_WORKER_PORT` 改监听端口，`LUMA_WORKER_DATA` 指定持久化目录。默认目录为启动位置下的 `luma-office-data`。保持一个工作器进程使用该目录；备份或搬迁时先停止进程再复制整个目录。任务和交付物存储在该目录的 SQLite 数据库，任务 ID 可在工作器重启后继续查询。

## 员工工作

进入员工工作台，点击「云电脑」。也能从一位员工已有的群聊交付物点击「云电脑处理」并编辑材料。排版会生成包含负责人和正文的 Markdown；任务表会把每行转换成一项待办，保留 `[x]` 完成标记，输出可在 Excel 打开的 CSV。只有点击「提交到云电脑」后，插件才会发送当前员工姓名、标题、所选操作和输入框中的材料。

启用「用云端模型起草」时，在工作器环境配置以下项目，重新启动后点击「测试连接」核对能力。

| 环境变量 | 值 |
| --- | --- |
| LUMA_WORKER_MODEL_URL | 兼容 Chat Completions 的服务基础地址，例如本机模型的 http://127.0.0.1:8080/v1 |
| LUMA_WORKER_MODEL | 该服务已安装或可用的模型标识 |
| LUMA_WORKER_MODEL_KEY | 该服务要求的 API 密钥。本机免密模型可以留空 |

写作模式会将姓名与材料发送给上述模型服务，可能产生该服务的用量。员工可用服务器模型撰写报告、编辑文字和起草文档。工作器只执行上述三种办公任务。所有交付物都可以回到发起员工的「云电脑」下载。

## 连接和恢复

看到「待确认」时先点「查询状态」。如果连接中断发生在远端收到任务之前，可以点「重试同一任务」；工作器会按原任务编号去重。工作器重启时会将仍在写作的任务标为失败，已经完成的交付物继续可用。在插件中断开连接后，本机已经收到的交付物仍可下载。

点击「停止云任务」会向对应工作器发送停止请求，中止进行中的模型连接，并保留已停止的任务记录。若服务器离线，界面会显示错误，可以在重新连上同一台服务器后再停止。远端模型提供商对已处理部分的计费取决于其服务条款。

连接令牌在 Windows 上使用当前用户的 DPAPI 保存。服务端鉴权采用 Bearer 令牌。协议为 `luma-office/1`。与 OpenMausBot 的电脑连接设计可参考其[项目说明](https://github.com/milind-soni/OpenMausBot)；本目录提供 Luma 的自托管文档工作器，插件的地址须指向此工作器。
