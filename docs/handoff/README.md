## 旧机实际版本与正式版的关系

旧机插件在 DSH 中显示为 0.6.7。旧公开标签只包含当时发布的桌宠等改动，随后安装到本机的版本又更新了「联系」、角色记忆及工作室群聊。此次用最后安装版的已验证源码构建 0.6.8。群聊现在支持同事根据前文接话、点名与收束讨论，能力菜单附有解释，「成员与风格」和工作室导航可按需展开。现有档案仍可读取。

与旧机最终安装目录逐个对照，两包均有 2,139 个文件。2,010 个公共资源和 100 张原生桌宠图逐字节一致。完整 ZIP、更新包及从 0.4.3 基础目录恢复出的新目录已核对全部 2,139 个文件。Windows 原生及宿主测试 90 项、前端测试 349 项通过。新电脑的 DSH、显示器 DPI、显卡和模型登录仍需在目标机器实测。

## 换设备清单

### 先让正式版在新设备运行

- [ ] 在 Windows 上安装并启动一次 DeepSeek Harness Desktop。解压完整插件到一个长期保留的位置，从 DSH 的插件页添加其中含 `package.json` 的 `DesktopPlugin-0.6.8` 目录，重开宿主，查看版本与运行状态。也可解压小安装器，双击 `Install-Luma-DSH.cmd`。[安装手册](../guide.md)
- [ ] 如果要接着旧设备的收藏和偏好，从旧机「插件设置」导出并经自己的私有渠道带走。已有会话、员工记忆与工作记录需另外迁移对应 DSH 档案和使用中的爱之屋数据。模型服务与本机客户端在新机重新登录或绑定，再测一次角色私聊。公开下载只包含软件、工程和美术。[数据与记忆说明](../memory.md)
- [ ] 进入经典办公室，让陆弥与现有伙伴在同一镜头、同一落点对照站姿。确认联系人能打开、已有群能接话，再打开一次桌宠、点播动作及一次文件问答。[同镜头实测](../images/office-standing-installed-scale.png)

### 再恢复开发工作区

从 PowerShell 运行，最后一个命令会让工作分支从这次发布的源码起步。

```powershell
git clone https://github.com/myflww/luma-dsh-plugin.git
Set-Location luma-dsh-plugin
git switch -c codex/continue-pet-art v0.6.8
```

安装 Node.js 24 后，从仓库根目录进入 `developer`。下例假设已把完整插件解压到 `D:\Luma\DesktopPlugin-0.6.8`，改成新机的实际位置即可。

```powershell
Set-Location developer
npm ci
.\restore-public.ps1 -Archive 'D:\Luma\DesktopPlugin-0.6.8'
npm run build
$env:LUMA_TEST_WINDOWS_UI = '1'
npm test
```

- [ ] 解压交接资料，分别打开两份技术子包的说明。旧试验补丁先在其说明指明的旧基线复原并检查，再把需要的修改移植到 0.6.8。桌面、办公室和卧室须引用同一套造型索引。
- [ ] 解压已审美术到单独的制作目录。先对索引和 SHA-256，保留长宽、透明通道和原格顺序，再按实际落点在游戏内复验。单图合格与跨场景接入是两项验收。
- [ ] 第一轮只做一个角色的一种附加提姿，以及经典办公室北排右席的原装陆弥坐姿。分别保存同落点、同缩放的前后画面。确认动作连贯、服装合适，再扩展衣装与席位。
- [ ] 完成后核对正式包、原生桌宠和房间各自的资源清单，跑自动化测试，并记录哪些场景真正做过人工复核。[开发与打包](../../developer/README.md) · [历史场景验收](../scene-verification.md)

给新设备的接手窗口可以直接复制以下任务。

> 从 GitHub 的 v0.6.8 和 docs/handoff/README.md 开始。先确认本机正在运行的插件版本，读取工位、拖拽和桌宠三份任务书。保留陆弥原装与换装各自的人设，始终按实装伙伴同场景定尺。优先试接已经审核的鲸鱼娘换装提起动作，并在经典办公室北排右席用原装陆弥验证坐骨、手和前景遮挡。逐项回报完成、待复验、仍缺原画的内容。
